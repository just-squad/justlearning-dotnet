# **Делегаты, события, лямбда-выражения**

**Цель**: Понять, как создавать гибкие системы с обратными вызовами.

---

## **Делегаты (Delegates)**

### **Что такое делегат?**

Делегат — это **типобезопасный указатель на метод**, который определяет сигнатуру вызываемого метода. По сути, это объект, который хранит ссылку на метод.

### **Виды делегатов**

1. **Пользовательские делегаты** (объявляются вручную)
2. **Встроенные обобщённые делегаты** (`Func`, `Action`, `Predicate`)

#### **Пример 1: Пользовательский делегат**

```csharp
delegate int MathOperation(int a, int b); // Объявление

class Calculator
{
    public static int Add(int a, int b) => a + b;
    public static int Multiply(int a, int b) => a * b;
}

// Использование
MathOperation op = Calculator.Add;
int result = op(2, 3); // 5
op = Calculator.Multiply;
result = op(2, 3); // 6
```

#### **Пример 2: Встроенные делегаты**

```csharp
Func<int, int, int> add = (a, b) => a + b; // Func<in, in, out>
Action<string> log = message => Console.WriteLine(message); // Action<in>
Predicate<int> isEven = num => num % 2 == 0; // Predicate<in> (возвращает bool)
```

### **Где хранятся делегаты?**

- **Делегат** — это **ссылочный тип**, поэтому хранится в **куче (Heap)**.
- **Ссылка на делегат** (если он объявлен локально) хранится в **стеке (Stack)**.

---

## **События (Events)**

### **Что такое событие?**

Событие — это **механизм уведомления**, основанный на делегатах. Позволяет объектам подписываться на действия.

#### **Пример: Класс кнопки**

```csharp
class Button
{
    public event Action Clicked; // Событие

    public void Click()
    {
        Clicked?.Invoke(); // Вызов события
    }
}

// Подписка
var button = new Button();
button.Clicked += () => Console.WriteLine("Кнопка нажата!");
button.Click(); // Выведет "Кнопка нажата!"
```

### **Где хранятся события?**

- **Событие** — это **обёртка над делегатом**, поэтому тоже хранится в **куче**.
- **Подписчики** (методы) хранятся в **делегате (в куче)**.

---

## **Лямбда-выражения**

### **Что такое лямбда?**

Лямбда — это **анонимная функция**, которая может быть преобразована в делегат или дерево выражений (`Expression<T>`).

#### **Пример 1: Простая лямбда**

```csharp
Func<int, int> square = x => x * x;
Console.WriteLine(square(5)); // 25
```

#### **Пример 2: Лямбда с несколькими параметрами**

```csharp
Func<int, int, int> sum = (a, b) => a + b;
```

#### **Пример 3: Лямбда как обработчик события**

```csharp
button.Clicked += () => Console.WriteLine("Лямбда-обработчик");
```

### **Где хранятся лямбды?**

- **Лямбда без замыкания** компилируется в **статический метод** (хранится в **куче**).
- **Лямбда с замыканием** (использует внешние переменные) создаёт **класс-замыкание** (хранится в **куче**).

---

## **Замыкания (Closures)**

### **Что такое замыкание?**

Замыкание — это **лямбда, которая захватывает внешние переменные**.

#### **Пример:**

```csharp
int multiplier = 2;
Func<int, int> multiply = x => x * multiplier; // Захватывает multiplier
Console.WriteLine(multiply(5)); // 10
multiplier = 3;
Console.WriteLine(multiply(5)); // 15 (значение изменилось!)
```

### **Где хранятся замыкания?**

- **Внешние переменные** помещаются в **класс-замыкание** (в **куче**).
- **Лямбда** становится методом этого класса.

---

## **Когда использовать, а когда избегать?**

### **✅ Хорошие практики**

1. **Делегаты**:

   - Коллбэки (например, в асинхронном коде).
   - Стратегии (паттерн Strategy).
   - LINQ (`Where`, `Select`).

2. **События**:

   - UI-логика (кнопки, уведомления).
   - Observer-паттерн (подписка/отписка).

3. **Лямбды**:
   - Краткие однострочники (`list.Where(x => x > 5)`).
   - Анонимные обработчики (`button.Click += () => ...`).

### **❌ Плохие практики**

1. **Делегаты**:

   - Избыточное использование вместо интерфейсов.
   - Долгие методы в лямбдах (нарушает читаемость).

2. **События**:

   - Утечки памяти (не отписываемся от событий).
   - Слишком много подписчиков (замедляет выполнение).

3. **Лямбды**:
   - Сложные многострочные лямбды (лучше вынести в метод).
   - Замыкания в высоконагруженных циклах (накладные расходы).

---

## **Производительность и память**

### **Делегаты**

- **Вызов делегата** немного медленнее, чем вызов метода напрямую.
- **Потребление памяти**: Каждый делегат — объект в куче.

### **События**

- **Подписка/отписка** требует управления списком делегатов.
- **Утечки памяти**, если не отписаться (`+=` без `-=`).

### **Лямбды**

- **Без замыканий**: Оптимизируются в статические методы.
- **С замыканиями**: Дополнительный объект в куче.

---

## **Примеры из реальных проектов**

### **Делегаты в LINQ**

```csharp
var numbers = new List<int> { 1, 2, 3, 4, 5 };
var evenNumbers = numbers.Where(x => x % 2 == 0); // Лямбда как делегат
```

### **События в UI (WPF)**

```csharp
public class MainWindow : Window
{
    public MainWindow()
    {
        var button = new Button();
        button.Click += (sender, args) => MessageBox.Show("Clicked!");
    }
}
```

### **Замыкания в асинхронном коде**

```csharp
for (int i = 0; i < 10; i++)
{
    Task.Run(() => Console.WriteLine(i)); // Будет выводить 10 раз 10!
}
// Решение:
for (int i = 0; i < 10; i++)
{
    int temp = i; // Копия для замыкания
    Task.Run(() => Console.WriteLine(temp)); // Теперь выводит 0..9
}
```

---

## **Выводы**

1. **Делегаты** — мощный инструмент для обратных вызовов и гибкости.
2. **События** — лучший способ реализовать Observer-паттерн.
3. **Лямбды** — удобны для кратких операций, но могут ухудшать читаемость.
4. **Замыкания** — полезны, но могут приводить к утечкам памяти.
5. **Производительность**:
   - Делегаты чуть медленнее методов.
   - Лямбды с замыканиями создают объекты в куче.

**Главное правило**:  
_"Используй делегаты и лямбды там, где они упрощают код, но избегайте избыточности."_
