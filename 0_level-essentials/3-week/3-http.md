# **Работа с HTTP: запросы, ответы, статус-коды**

**Цель**: Правильно формировать HTTP-ответы и понимать статус-коды. Будем рассматривать на примере "Почтовой Службы" — представь, что HTTP это система доставки писем между клиентом и сервером

## **Основы HTTP**

**HTTP (HyperText Transfer Protocol)** — протокол передачи данных в формате "запрос-ответ".

**Ключевые характеристики:**

- **Без состояния (Stateless)** — каждый запрос независим (сервер не помнит предыдущие запросы)
- **Работает поверх TCP/IP**
- **Порт по умолчанию:** 80 (HTTP), 443 (HTTPS)

**Аналогия:**

- Клиент = Отправитель письма
- Сервер = Почтовое отделение
- Запрос = Конверт с вопросом
- Ответ = Конверт с результатом

---

## **Структура HTTP Запроса (Request)**

**Пример запроса:**

```http
POST /api/books HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer xyz123

{
  "title": "Clean Code",
  "author": "Robert Martin"
}
```

**Компоненты:**

1. **Стартовая строка:**

   - `POST` — HTTP-метод
   - `/api/books` — путь к ресурсу
   - `HTTP/1.1` — версия протокола

2. **Заголовки (Headers):**

   ```http
   Host: example.com             // Домен сервера
   Content-Type: application/json // Формат данных
   Authorization: Bearer xyz123   // Токен доступа
   User-Agent: Postman/1.0        // Клиентское ПО
   Accept: application/json       // Ожидаемый формат ответа
   ```

3. **Тело запроса (Body):**
   - Данные в формате JSON/XML/text (опционально)
   - Для GET-запросов тело обычно отсутствует

---

## **HTTP Методы (Глаголы)**

| Метод    | Описание                  | Пример из жизни                      |
| -------- | ------------------------- | ------------------------------------ |
| `GET`    | Получить данные           | "Пришлите каталог книг"              |
| `POST`   | Создать новый ресурс      | "Отправьте новую книгу в библиотеку" |
| `PUT`    | Полное обновление ресурса | "Замените все данные книги ID=5"     |
| `PATCH`  | Частичное обновление      | "Обновите только цену книги ID=5"    |
| `DELETE` | Удалить ресурс            | "Удалите книгу ID=5"                 |
| `HEAD`   | Получить только заголовки | "Есть ли книга ID=5? (без тела)"     |

---

## **HTTP Ответ (Response)**

**Пример ответа:**

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/books/42
Date: Mon, 27 May 2024 10:00:00 GMT

{
  "id": 42,
  "title": "Clean Code",
  "author": "Robert Martin"
}
```

**Компоненты:**

1. **Строка статуса:**

   - `HTTP/1.1` — версия протокола
   - `201 Created` — код и текст статуса

2. **Заголовки:**

   ```http
   Content-Type: application/json  // Формат данных
   Location: /api/books/42         // Ссылка на новый ресурс
   Date: ...                       // Время ответа
   ```

3. **Тело ответа (Body):**
   - Данные в заявленном формате
   - Может отсутствовать (например, для статуса 204)

## **HTTP Коды Состояния (Status Codes)**

**Классификация по первым цифрам:**

| Код | Категория       | Популярные коды               | Пример из жизни                      |
| --- | --------------- | ----------------------------- | ------------------------------------ |
| 1xx | Информационные  | 100 Continue                  | "Продолжайте отправку данных"        |
| 2xx | Успех           | **200 OK**                    | "Ваш запрос успешно обработан"       |
|     |                 | 201 Created                   | "Книга успешно создана"              |
|     |                 | **204 No Content**            | "Удаление прошло успешно (нет тела)" |
| 3xx | Перенаправление | 301 Moved Permanently         | "Книга теперь в другом разделе"      |
|     |                 | **304 Not Modified**          | "Данные не изменились (кеш)"         |
| 4xx | Ошибка клиента  | **400 Bad Request**           | "Неправильный формат запроса"        |
|     |                 | **401 Unauthorized**          | "Требуется авторизация"              |
|     |                 | **403 Forbidden**             | "Доступ запрещен"                    |
|     |                 | **404 Not Found**             | "Книга не найдена"                   |
|     |                 | 405 Method Not Allowed        | "DELETE не поддерживается"           |
| 5xx | Ошибка сервера  | **500 Internal Server Error** | "Ошибка на сервере"                  |
|     |                 | 502 Bad Gateway               | "Проблема с прокси-сервером"         |
|     |                 | 503 Service Unavailable       | "Сервер перегружен"                  |

**Важные нюансы:**

- 401 vs 403:
  - 401 — "Вы не представились"
  - 403 — "Вы представились, но доступа нет"

   ```http

   ```

## **Лучшие Практики**

1. Всегда возвращайте **корректные статус-коды**
2. Используйте **DTO** вместо прямого возврата моделей БД
3. **Валидируйте входные данные**
4. Для ошибок используйте **ProblemDetails** (RFC 7807):

   ```json
   {
     "type": "https://example.com/errors/not-found",
     "title": "Book not found",
     "status": 404,
     "detail": "Book with id 42 does not exist"
   }
   ```

5. **Версионируйте API** (`/api/v1/books`)

## **Пример: Полный Жизненный Цикл**

**Сценарий:** Добавление книги в библиотеку

1. **Клиент → Сервер (Запрос):**

   ```http
   POST /api/books HTTP/1.1
   Content-Type: application/json

   {"title": "Domain-Driven Design", "author": "Eric Evans"}
   ```

2. **Серверная обработка:**

   - Middleware: Проверка CORS, логирование
   - Маршрутизация → BooksController.Create()
   - Валидация данных → сохранение в БД

3. **Сервер → Клиент (Ответ):**

   ```http
   HTTP/1.1 201 Created
   Location: /api/books/123
   Content-Type: application/json

   {"id": 123, "title": "Domain-Driven Design", "author": "Eric Evans"}
   ```

---

**Ключевые выводы:**

1. HTTP = протокол обмена структурированными сообщениями
2. Статус-коды — язык понимания результатов операций
3. ASP.NET Core абстрагирует низкоуровневые детали, но понимание HTTP критически важно
