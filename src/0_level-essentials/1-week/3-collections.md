# **Коллекции и LINQ**

**Цель**: Работать с наборами данных (списки, словари) и выполнять запросы.

Коллекции — это "рабочие лошадки" любого приложения. Они позволяют хранить, организовывать и эффективно работать с наборами данных. В C# существует богатая иерархия коллекций, и правильный выбор типа коллекции может значительно повлиять на производительность приложения.

---

## **Основные типы коллекций и их внутреннее устройство**

### List\<T> — динамический массив

**Структура:** Внутри использует массив, который автоматически увеличивается при необходимости  
**Память:** Элементы хранятся в непрерывном блоке памяти  
**Сложность операций:**

- Добавление: O(1) (амортизированное)
- Вставка: O(n)
- Доступ по индексу: O(1)
- Поиск: O(n)

```csharp
List<int> numbers = new List<int> { 1, 2, 3 };
numbers.Add(4); // Быстрое добавление
numbers.Insert(0, 0); // Медленная вставка в начало
```

### Dictionary<TKey, TValue> — хеш-таблица

**Структура:** Хранит пары ключ-значение в бакетах, используя хеш-код ключа  
**Память:** Элементы распределены по бакетам (не непрерывно)  
**Сложность операций:**

- Добавление: O(1) (в среднем)
- Поиск: O(1) (в среднем)
- Удаление: O(1) (в среднем)

```csharp
Dictionary<string, int> ages = new Dictionary<string, int>();
ages["Alice"] = 30; // Быстрое добавление
if (ages.TryGetValue("Bob", out int age)) { ... }
```

### HashSet\<T> — множество уникальных элементов

**Структура:** Аналогична Dictionary, но без значений (только ключи)  
**Сложность операций:**

- Добавление: O(1)
- Проверка наличия: O(1)
- Операции множества (Union, Intersect): O(n)

```csharp
HashSet<string> uniqueNames = new HashSet<string>();
uniqueNames.Add("Alice"); // Возвращает true, если элемента не было
```

### LinkedList\<T> — двусвязный список

**Структура:** Элементы хранятся в узлах, связанных ссылками  
**Память:** Элементы распределены в памяти  
**Сложность операций:**

- Вставка/удаление в известной позиции: O(1)
- Поиск: O(n)
- Доступ по индексу: O(n)

```csharp
LinkedList<int> list = new LinkedList<int>();
list.AddLast(1); // Быстрая вставка в конец
list.AddFirst(0); // Быстрая вставка в начало
```

### Queue\<T> и Stack\<T> — специализированные коллекции

**Queue (FIFO):**

```csharp
Queue<string> queue = new Queue<string>();
queue.Enqueue("first");
queue.Enqueue("second");
string first = queue.Dequeue(); // "first"
```

**Stack (LIFO):**

```csharp
Stack<string> stack = new Stack<string>();
stack.Push("first");
stack.Push("second");
string top = stack.Pop(); // "second"
```

## **Алгоритмическая сложность основных операций**

| Коллекция       | Добавление | Удаление | Поиск | Доступ по индексу | Память |
| --------------- | ---------- | -------- | ----- | ----------------- | ------ |
| List\<T>        | O(1)\*     | O(n)     | O(n)  | O(1)              | Low    |
| Dictionary<K,V> | O(1)       | O(1)     | O(1)  | N/A               | High   |
| HashSet\<T>     | O(1)       | O(1)     | O(1)  | N/A               | High   |
| LinkedList\<T>  | O(1)       | O(1)\*\* | O(n)  | N/A               | High   |
| Queue\<T>       | O(1)       | O(1)     | N/A   | N/A               | Low    |
| Stack\<T>       | O(1)       | O(1)     | N/A   | N/A               | Low    |

\*Амортизированная сложность  
\*\*При известном местоположении элемента

## **Лучшие практики и выбор коллекций**

### Когда использовать

- **List\<T>**:

  - Когда нужен частый доступ по индексу
  - Последовательная обработка элементов
  - Пример: Список элементов на странице

- **Dictionary<TKey, TValue>**:

  - Быстрый поиск по ключу
  - Уникальные ключи
  - Пример: Кэш данных

- **HashSet\<T>**:

  - Проверка уникальности
  - Операции с множествами
  - Пример: Фильтрация дубликатов

- **LinkedList\<T>**:

  - Частые вставки/удаления в середине
  - Реализация собственных структур данных
  - Пример: История действий с возможностью отмены

- **Queue\<T>/Stack\<T>**:
  - Обработка в порядке FIFO/LIFO
  - Пример: Очередь заданий, стек вызовов

### Подводные камни

1. **Размер коллекции**:

   - Для List указывайте начальную емкость, если она известна

   ```csharp
   List<int> list = new List<int>(1000); // Уменьшает количество копирований
   ```

2. **Коллизии в Dictionary**:

   - Реализуйте правильные GetHashCode() и Equals() для ключей
   - Используйте IEqualityComparer для сложных ключей

3. **Боксингинг**:

   - Избегайте коллекций с типами значений (struct) в .NET Framework
   - Используйте обобщенные коллекции (List\<int> вместо ArrayList)

4. **Потокобезопасность**:

   - Большинство коллекций не потокобезопасны
   - Используйте ConcurrentCollections для многопоточности

   ```csharp
   ConcurrentDictionary<string, int> safeDict = new ConcurrentDictionary<string, int>();
   ```

5. **Итерация и модификация**:
   - Не изменяйте коллекцию во время итерации
   - Используйте ToList() для создания копии при итерации

## **Продвинутые коллекции**

### Sorted Collections

- **SortedList<TKey, TValue>**:

  - Автоматическая сортировка по ключу
  - Доступ по индексу и ключу
  - Сложность вставки: O(n)

- **SortedDictionary<TKey, TValue>**:
  - Реализован как красно-черное дерево
  - Сложность вставки/удаления: O(log n)

### Immutable Collections

- Коллекции, которые нельзя изменить после создания
- Потокобезопасны по умолчанию

```csharp
ImmutableList<int> immutable = ImmutableList.Create(1, 2, 3);
var newList = immutable.Add(4); // Создает новую коллекцию
```

### Memory-Optimized Collections

- **ArrayPool\<T>**: Переиспользование массивов
- **Span\<T>**: Работа с памятью без аллокаций

```csharp
var array = ArrayPool<int>.Shared.Rent(1024);
try {
    // Работа с массивом
}
finally {
    ArrayPool<int>.Shared.Return(array);
}
```

## **Производительность: ключевые советы**

1. **Выбор правильной коллекции**:

   - Для частых поисков — Dictionary/HashSet
   - Для частых вставок в середину — LinkedList
   - Для последовательной обработки — List/Array

2. **Инициализация с емкостью**:

   ```csharp
   Dictionary<string, int> dict = new Dictionary<string, int>(capacity: 1000);
   ```

3. **Значения vs Ссылки**:

   - Для struct используйте массивы
   - Избегайте больших struct в коллекциях

4. **LINQ и коллекции**:

   - Materialize запросы для многократного использования

   ```csharp
   var filtered = list.Where(x => x > 0).ToList();
   ```

5. **Профилирование**:
   - Используйте MemoryDiagnoser и BenchmarkDotNet
   - Анализируйте аллокации памяти

## **Примеры оптимизаций**

### Эффективная конкатенация строк

```csharp
List<string> parts = new List<string>();
// Вместо множества конкатенаций
foreach (var item in collection)
{
    parts.Add(item.ToString());
}
string result = string.Join("", parts);
```

### Быстрая очистка коллекции

```csharp
List<int> list = new List<int>(10000);
// Вместо list.Clear() (сохраняет внутренний массив)
list = new List<int>(); // Может быть быстрее для больших коллекций
```

### Использование структур

```csharp
public struct Point { public int X, Y; }

// Лучше для производительности, но осторожно с боксингом
List<Point> points = new List<Point>();
```

## **Заключение: Главные правила работы с коллекциями**

1. **Знай свою коллекцию**: Понимай внутреннее устройство и сложность операций
2. **Выбирай с умом**: Нет универсальной "лучшей" коллекции — все зависит от сценария
3. **Профилируй**: Реальная производительность может отличаться от теории
4. **Оптимизируй память**: Большие коллекции требуют особого подхода
5. **Используй современные API**: Span\<T>, Memory\<T>, ArrayPool
6. **Не забывай о безопасности**: Используй ImmutableCollections для многопоточности

Правильный выбор коллекции — это баланс между скоростью операций, использованием памяти и удобством разработки. Экспериментируйте, измеряйте и выбирайте оптимальное решение для каждой конкретной задачи.

## **LINQ to Object**

Язык запросов к коллекциям. Пример: найти все четные числа.

```csharp
List<int> numbers = new List<int> { 1, 2, 3, 4, 5 };
var evenNumbers = numbers.Where(n => n % 2 == 0).ToList(); // [2, 4]
```
