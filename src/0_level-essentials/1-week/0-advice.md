## CLI команды, которые следует знать

### mkdir

`mkdir` - (make directory) создание папки с каким то названием.

Использование:

```bash
mkdir <name-of-new-directory>

mkdir new-folder
mkdir todo-list
```

### cd

`cd` - (change directory) поменять текущую рабочую директорию на указанную.

Ключевые знаки:

- `.` - производить поиск по директории начиная от текущей рабочей директории.
- `~` - домашняя директория текущего пользователя в системе.
- `-` - вернуться на в предыдущую папку. Например если сделать переход `cd /some`, потом `cd /another`, а затем `cd -`, то мы вернемся в директорию `/some`

Использование:

```bash
cd <path-to-target-directory>

cd ./programming/todo-list
cd /home
cd ~
cd -
```

## Создание простейшего консольного приложения

С течением времени у DotNET проектов устоялся стандартизированный вид расположения файлов и проектов в решении. И выглядит это таким образом.

```text
project-name
    |- src
        |- ProjectName.Api
            |- ... (folders with classes)
            |- ProjectName.Api.csproj
            |- ... (classes)
        |- ProjectName.ApplicationServices
            |- ... (folders with classes)
            |- ProjectName.ApplicationServices.csproj
            |- ... (classes)
        |- ProjectName.Domain
            |- ... (folders with classes)
            |- ProjectName.Domain.csproj
            |- ... (classes)
        ...
    |- tests
        |- ProjectName.Domain.UnitTests
            |- ProjectName.Domain.UnitTests.csproj
            |- ... (tests)
        |- ProjectName.IntegrationTests
            |- ProjectName.IntegrationTests.csproj
            |- ... (tests, fixtures, etc)
    |- Directory.Build.props
    |- Directory.Build.targets
    |- ProjectName.sln
```

Так как мы хотим стать настоящими программистами, то создавать проекты будем через вызовы команд утилит командной строки.

1. Убедитесь, что у вас установлен DotNET SDK, для этого в привычной оболочке командной строки (в каждой ОС свое приложение) введите команду `dotnet --list-sdks`. Если команда выполнится и там выведется хотя-бы одна строка, то можно продолжать изучение. Если нет, то необходимо поставить пакет разработки. Для этого идем [на этот сайт](https://dotnet.microsoft.com/en-us/download) и устанавливаем рекомендуемый пакет.
2. Выбираем папку, в которой у нас будет располагаться проект. Я обычно про это выделяю отдельную папку (`programming`, `repos` или любую другую в директории текущего пользователя системы)
3. Создаем папку с названием своего будущего проекта. Если мы хотим сделать планировщик задач, то его можно назвать, как `todo-list`. Для этого в командной строке, в той директории где у нас будут располагаться проекты, выполняем команду `mkdir todo-list`. Переходим в созданную папку используя команду `cd todo-list`
4. Создаем файл решения используя команду `dotnet new sln -n <NameOfSolution>`. Подробнее про файл решения можно почитать [тут](https://learn.microsoft.com/ru-ru/visualstudio/extensibility/internals/solution-dot-sln-file?view=vs-2022)
5. Создаем папку в которой будут находиться проекты, так как это просто консольное приложение, то нам пока достаточно одного проекта. Потом если что, можно добавить другие. Создаем папку `mkdir src`. Заходим в эту папку с исходниками.
6. Создаем свой проект. Так как это консольное приложение то для команды `dotnet new` нужно указать шаблон `console`. И получится такая команда `dotnet new console -n <NameOfProject>`. Чтобы увидеть полный список доступных шаблонов для создания проектов можно вызвать команду `dotnet new list`. Чаще всего в веб разработке используются такие шаблоны как `web`, `classlib` и в целом все. Все остальное можно сделать руками, добавляя те или иные зависимости в проект.
7. Добавление созданного проекта в решение. Для этого возвращаемся в папку где располагается наше решение. Если мы находимся еще в папке `src` то выполняем команду `cd ..`. Теперь добавляем созданный проект в решение через команду `dotnet sln <path-to-sln> add <path-to-csproj>`. Представим что решение называется `BestSolution` а сам проект как `BestProject`, тогда в этом примере команда будет выглядеть так `dotnet sln ./BestSolution.sln add ./src/BestProject/BestProject.csproj`
8. На этом базовая настройка решения завершена. Теперь можно открывать в любом удобной IDE и продолжать разработку.
